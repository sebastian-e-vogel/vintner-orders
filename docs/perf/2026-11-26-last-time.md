# Last-time query: one row per source (#93)

Database `vintner_perf` (scale seed, 20,000 order requests). SQL: Q4a (heavy customer, 35,873 orders) and Q4b (light customer, 6 orders) from `queries.sql`. Third run of each, as the README says. k6: 10 VUs, 30 s steady, no pauses, API built and run on the host (Apple M1).

## What changed

`newestSql` in `apps/api/src/customers/customers.service.ts` now takes `ORDER BY ... LIMIT 1` inside each `UNION ALL` branch, so each source reads its newest row through its `(customer_id, date)` index. The sales rep name is looked up once, for the winning row. No migration: both indexes already existed. Same tie rule: newest first, the order beats the request, then the lowest id.
